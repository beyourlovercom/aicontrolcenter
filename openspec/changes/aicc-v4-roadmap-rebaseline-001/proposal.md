## Why

AICC V3 is sealed and active on `main`, but the legacy Living Roadmap still carried historical M4.1 current-state language. V4 needs one unambiguous canonical roadmap and an explicit effort baseline before any new runtime capability is authorized.

## What Changes

- Establish `AICC-V4-LIVING-ROADMAP.md` as the canonical next-development roadmap.
- Reclassify legacy V2/M4 current-state language as historical traceability.
- Record V4.0–V4.8 delivery order and engineering/CI/UAT effort ranges.
- Add the formal `AICC-V4-ROADMAP-REBASELINE-001` Work Package and documentation regression checks.

## Explicit Exclusions

No runtime source changes, OpenSpec Apply/Sync/Archive, self-authorization, automatic next-WP execution, PR merge, release, deployment, or V4.1 implementation. `AICC-CONTROL-LOOP-001B` remains `PLANNED / NOT_AUTHORIZED`.
